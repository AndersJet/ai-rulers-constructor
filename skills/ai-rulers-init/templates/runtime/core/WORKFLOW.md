# 任务执行流程

```yaml
metadata:
  applies_to:
    - "**/*"
  trigger_keywords:
    - core
  must_load_with: []
```

1. 明确目标、影响范围与可观察的成功标准；读取目标文件及直接依赖，复用已存在模式。
2. 运行入口给出的 Context 命令（由 RULERS_STATE.json 派生），选择命中领域；按返回的加载清单读取规则与已审阅画像的相关部分。
3. 按任务风险实施最小一致变更；事实变化时先核对已批准决定，规则变化时进入维护流程。
4. 执行项目画像中适用的验证命令；报告结果与下一步，长任务记录足以恢复的检查点。

## 条件参考

- 修改规则结构或内容：读取 `{{RULERS_DIR}}/core/RULER_MAINTENANCE.md`。
- 规则权威或所有权冲突：读取 `{{RULERS_DIR}}/core/DOC_GOVERNANCE.md`。
- 提交：遵循项目已有提交和发布约定；入口若配置专用策略，按入口的条件路由加载。
- 绿地：以已批准决策约束实施；棕地：以已观察事实结合批准的变更约束实施。

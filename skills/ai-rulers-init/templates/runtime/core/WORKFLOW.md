# 任务执行流程

```yaml
metadata:
  applies_to:
    - "**/*"
  trigger_keywords:
    - core
  must_load_with: []
```

1. 明确目标、影响范围与可观察的成功标准；读取目标文件及直接依赖，复用已存在模式。
2. 运行入口给出的 Context 命令（由 RULERS_STATE.json 派生），选择命中领域；按返回的加载清单读取规则与已审阅画像的相关部分。
3. 按任务风险实施最小一致变更；事实变化时先核对已批准决定，规则变化时进入维护流程。
4. 按变更影响选择项目画像中的必要验证命令，并执行项目必需门禁；报告结果及未覆盖范围，长任务记录足以恢复的检查点。

## 条件参考

- 修改规则结构或内容：读取 `{{RULERS_DIR}}/core/RULER_MAINTENANCE.md`。
- 规则权威或所有权冲突：读取 `{{RULERS_DIR}}/core/DOC_GOVERNANCE.md`。
- 分支、worktree、PR/MR 或 CI：读取画像中的项目工作流权威指针，按实际约定创建或复用分支、选择工作区，履行 CI 观察、诊断和合并分工；缺少本次任务所需决定时再确认。
- 提交或推送：执行项目规定的提交门禁、实际 hook 和平台必需检查；不因画像列有命令就重跑全套。入口配置专用提交策略时，按条件路由加载；各动作分别依据当前授权执行。
- 绿地：以已批准决策约束实施；棕地：以已观察事实结合批准的变更约束实施。

# 任务执行流程

```yaml
metadata:
  applies_to:
    - "**/*"
  trigger_keywords:
    - core
  must_load_with: []
```

1. 明确本轮目标、阶段（访谈、规划、研究或实施）、影响范围与完成标准。缺少影响正确性、范围或授权的必要决定时暂停依赖工作，继续可独立推进的部分；已授权范围内的常规实施细节自行处理。阶段完成后结束，不自行扩大任务。
2. 使用入口建立的有效上下文，读取目标文件及直接依赖，复用项目既有模式。
3. 按任务风险实施最小一致变更；事实变化时先核对已批准决定，规则变化时进入维护流程。
4. 行为变更使用目标项目测试验证可观察行为、契约或数据不变量；回归测试应能暴露原缺陷。按影响选择必要命令并执行项目必需门禁；无法运行时说明替代验证和覆盖缺口。没有新变化、失败或未解决风险时不重复扩大验证。长任务保存可恢复检查点。

## 条件参考

- 分支、worktree、PR/MR 或 CI：读取画像中的项目工作流权威指针；外部技能的分支与隔离默认按项目约定及宿主能力适配，核对起点与 upstream，优先复用适用工作区。履行 CI 观察、诊断和合并分工；缺少本次任务所需决定时再确认。
- 提交或推送：执行项目规定的提交门禁、实际 hook 和平台必需检查；不因画像列有命令就重跑全套。入口配置专用提交策略时，按条件路由加载；各动作分别依据当前授权执行。
- 绿地：以已批准决策约束实施；棕地：以已观察事实结合批准的变更约束实施。

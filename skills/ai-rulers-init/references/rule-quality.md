# 规则内容判断

准备生成或维护候选时读取。本文指导规则作者，不进入目标项目的日常加载清单。

## 保留什么

优先记录项目独有知识、批准决定、非标准操作、真实失败模式和验收条件。必要的安全、
授权、数据与业务不变量保留；不以字数、文件数或模型通常知道某项知识为删除依据。
可从权威配置直接获取的事实引用其来源，通用教程与无项目依据的偏好不填入候选。

每项要求表达适用任务、需要保护的行为、依据与验证线索。例如，项目确有相应退款
约束时，说明重复回调不得重复退款及其契约/测试来源，而非追加“充分测试、保证质量”。
示例不作为目标事实；验证线索也不等于测试已经执行或业务语义已获证明。

## 选择调整

先读相关正文、入口/索引、直接引用和真实加载依赖，核对项目证据与当前请求。

| 当前证据 | 动作 |
| --- | --- |
| 已有表达完整且可达 | 指出命中依据，无需改动 |
| 表达完整但任务未能发现 | 修正触发条件或导航，保留原权威正文 |
| 表达含糊、范围或决定已变 | 原位改写完整含义，移除被替代措辞 |
| 多处承载同一要求 | 按作用域合并、移动或引用，保留一个权威正文 |
| 有独立且必要的新要求 | 补入适合的叶子；确有独立专题才新建文件 |
| 过时、不适用或已有替代保障 | 核对必要保障后删除，维护引用和批准删除记录 |
| 单次疏漏尚不知原因 | 检查加载、宿主和执行证据，再决定是否改规则 |

比较语义而非仅比较句子；不同作用域、数据边界或风险条件下的相似要求可以并存。
用户要求新增时也可通过原位补充满足目的；用户明确指定的范围与保留要求优先，不能
以去重为由擅自扩大删除。信息不足时继续可完成的证据发现，仅必要决定留作未决。

## 组织与复核

项目知识沿用现有 spec、ADR、契约和配置权威；Profile 保存必要事实、决定与指针，
叶子表达任务约束，INDEX 导航。不要另建一份需求、任务状态或命令台账。
生成说明留在作者 reference 或模板 AI_FILL，移除候选中的模板路径和写作指令。

复核最终候选是否解决请求、保持适用范围、清除重复与失效内容、保留必要保障，以及
链接和真实依赖是否完整。合并或移动后仍须能按典型任务加载；依赖代表规则加载关系，
不冒充业务依赖图或 CI 选测结果。只报告实际变化、原因、验证及剩余问题，不逐条罗列
无关规则或“不适用”项。不增加逐条评分字段、关键词裁决或永久维护台账。

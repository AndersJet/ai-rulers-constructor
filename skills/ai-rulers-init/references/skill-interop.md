# 规划、研究与访谈技能互操作

仅在发现、生成或维护项目的跨技能工作流时读取。依据当前用户目标及项目权威适配外部技能，
不建立全局 Skill 优先表；本文不加入日常任务的运行态加载清单。

## 阶段与停点

先绑定本轮 Destination、ticket type 和完成标准。规划产出地图及下一步，研究产出有来源的
报告，访谈产出已回答决定及未决问题；只有本轮已授权实施才进入代码或规则改动。
沿用仍适用的明确人类回答，记录来源并关闭已解决票；新的未决选择等待真实回答。
历史回答可作为固定输入回放，但不能标作实时 HITL 或由代理充当人类。

## 工作区与委派

先读 Profile 指向的项目 Git/workflow 权威，再将技能的默认 workspace/branch 步骤映射到
项目允许且宿主支持的方式。隔离需求、命名分支、分支起点和 upstream 分别核对；适用的
既有工作区可复用，允许的 detached worktree 可满足隔离，不能从 remote 推断 tracking。
项目没有规定本次必需选择时，仅澄清影响下一步的缺口；不推广某一项目的分支命名或 MR 策略。

协调者在任务中明确 worker 身份、研究问题、输入指针、报告归属与回收位置，只委派一次。
已经受委派的研究者直接调查并交付自己的报告；需要新问题或不同职责时再说明额外委派理由。
并行研究各有文件归属，回收时核对来源、路径和内容身份，再按授权处理临时工作区。

## 文档归属与恢复

- ticket 保存过程、研究答复与 resolution，并链接报告。
- accepted ADR 保存长期决定并引用依据；CONTEXT 保存领域术语。
- Profile 保存当前有效事实、批准约束和权威指针；讨论记录不自动成为 approved 事实。

沿用各文档的已有维护约定，保留每项要求的一份权威正文。批准决定实际改变已绑定 Profile
或规则时才进入 reconcile 或 rules-plan；没有差异时在所属文档结束。

继续或分叉前核对地图来源、仓库/会话身份、有效范围、已回答选择和可复用工作区。
外部地图与 fork 历史不一致时先核验出处；用户明确改选后采用新范围，旧努力以 tracker 的
退休/替代记录保留指针。重建地图不包含删除分支、归档或清理未知修改的授权。
目录缺失时查归档、快照及成果落点，分别报告“工作区不可见”与“材料保全已证实”。
交接记录最终报告路径、内容身份、未决项及 branch/worktree/snapshot 状态；保全未证实的资产保持待核查。
